# Шаблон проєкту «Психологічна підтримка»

Бот психологічної підтримки за ТЗ Астарти, зібраний з нуля як проєкт OpenBP (`docs/projects.md` §6, ADR-005): дані,
ролі, сторінки психологів і координатора, підсценарії правил запису з `docs/psy-support.md` §4 (F8-08) і сценарій бота
`bot` — webhook Telegram, меню, екрани (F8-09); шедулер `scheduler` — нагадування, опитування, розсилки, слоти й
знеособлення (F8-10). Перенесення даних з Google Sheets — F8-11.

```bash
openbp import-project examples/projects/psy-support/bundle.json --url http://localhost:8088 --api-key $OPENBP_API_KEY
```

Після імпорту:

1. Підключіть конектор Telegram **тестового** бота (не продакшн «Astarta psy») і створіть змінну інстансу
   `psy_telegram_server` з id цього конектора («Налаштування» → «Змінні»). Через неї всі підсценарії надсилають
   повідомлення tool'ом `send_messages`; без змінної дії працюють, а надсилання завершується помилкою вузла, яка дію не
   скасовує.
2. У вкладці «Учасники» дайте координатору роль проєкту `editor` і роль застосунку «Координатор», психологам —
   `viewer` і «Психолог».
3. На сторінці «Психологи» заповніть психологів і в полі «Обліковий запис OpenBP» виберіть їхні облікові записи; у
   слотах, шаблонах і сеансах БСТ поле «Обліковий запис психолога» дає психологу сторінку «Мої слоти».
4. Бот — див. «Сценарій бота» нижче: credential секрету вебхука, `set_webhook`, активація сценарію `bot`.

Імпорт потребує credential типу `webhook.header` з назвою «Секрет вебхука бота психологічної підтримки» (або `mapping`
`cred_psy_bot_webhook` → id вашого credential) — створіть його до імпорту.

## Ролі

| Роль застосунку | Бачить |
|---|---|
| `coordinator` — Координатор | усі сторінки: розклад, записи, події, БСТ, матеріали, тексти бота, психологи, користувачі, журнал, показники |
| `psychologist` — Психолог | «Мої слоти», шаблони розкладу, записи на консультації (свої й колег, з іменем і телефоном — ТЗ §10), події з учасниками, сеанси БСТ з листом очікування, матеріали |

Телефони й `telegram_id` — чутливі колонки: їх бачать editor проєкту, admin і учасники з роллю застосунку, кожне читання
пишеться в аудит. Окремої ролі HR у шаблоні немає: показники бачить координатор.

## Сторінки

| Сторінка | Що на ній |
|---|---|
| Мої слоти (`my-slots`) | слоти психолога, відібрані за «Обліковим записом психолога» = поточний користувач |
| Розклад і слоти (`schedule`) | усі слоти; створення, зміна, видалення |
| Шаблони розкладу (`templates`) | тижневі шаблони (день 1 — пн … 7 — нд, час, тривалість, формат, період дії); дія «Згенерувати слоти» запускає `generate-slots` |
| Записи на консультації (`bookings`) | час, психолог, ім'я й телефон людини, стан; дія «Скасувати» — `cancel-booking` (будь-коли, людина отримує повідомлення) |
| Події (`events`), Подія (`event`) | події; картка з учасниками й оцінками, дія «Надіслати оголошення» — `send-notice` |
| Реєстрації на події (`registrations`) | учасники всіх подій; дія «Скасувати» — `cancel-registration` |
| Сеанси БСТ (`bst`), Сеанс БСТ (`bst-session`) | сеанси; картка із записаними й листом очікування, дія «Надіслати оголошення» |
| Записи на БСТ (`bst-bookings`) | дія «Скасувати» — `cancel-bst`, звільнене місце отримує перший у черзі |
| Матеріали (`materials`) | тексти, посилання й файли бібліотеки (вид і URL або `file_id` Telegram), стан, перегляди |
| Тексти бота (`texts`) | рядки `settings`: тексти `TEXT_*` і ліміти з `docs/psy-support.md` §3.1 |
| Психологи, Користувачі бота, Журнал | довідник психологів; користувачі з пошуком за іменем і телефоном; `audit_log` без персональних даних |
| Показники (`metrics`) | записи, скасування, заповненість слотів, реєстрації й оцінки подій, БСТ і черга, користувачі, перегляди |

Форми `*-new` / `*-edit` — створення й зміна рядка таблиці без ключової колонки (ключ рядка генерує OpenBP і на нього
посилаються колонки `ref`).

## Таблиці

`docs/psy-support.md` §3 без `staff_accounts` і `invites` (вхід — облікові записи OpenBP з ролями застосунку). Відхилення:

- ключ рядка — згенерований `_key` (крім `settings.key` і `counters.metric`); посилання — колонки `ref`;
- `bookings` має копію `starts_at`, `psychologist_id` та імені й телефону людини: ліміт активних записів рахується в одному
  `insertIf`, а сторінки показують запис без з'єднань;
- `psychologist_user` (тип `user`) у слотах, шаблонах, записах і сеансах — для сторінки «Мої слоти»;
- `event_registrations` і `bst_bookings` унікальні серед `active`: повторна реєстрація додає новий рядок, а не оновлює
  скасований — так місткість і повтор перевіряються одним атомарним `insertIf`;
- `events`/`bst_sessions` мають `notice_sent_text`: оголошення з тим самим текстом удруге не надсилається (правило 9).

## Підсценарії правил

Кожен приймає вхід бота (`{ telegram_id, … }`) або дії сторінки (`{ row, rowKey, user }`) і повертає
`{ ok, reason?, message, notifications[] , … }`: `message` — текст для людини, `notifications` — повідомлення іншим
(`{ chat_id, text, parse_mode?, reply_markup? }`), які той самий сценарій наприкінці надсилає в Telegram пакетами до 100.
Успішна дія пише рядок у `audit_log`.

| Сценарій | Вхід | `reason` відмови |
|---|---|---|
| `book-slot` | `telegram_id`, `slot_id` | `not_registered`, `slot_unavailable` (поза вікном [зараз + MIN_HOURS_BEFORE; зараз + HORIZON_DAYS], закритий, психолог не працює), `already_booked`, `slot_taken` (зокрема одночасний запис — `unique` таблиці), `limit` (MAX_ACTIVE_CONSULTS); успіх дає `calendar.google`/`calendar.outlook` з назвою «Особиста зустріч» |
| `cancel-booking` | `telegram_id`, `booking_id` або дія сторінки | `not_found`, `too_late` (з поштою психолога; лише для людини) |
| `move-booking` | `telegram_id`, `booking_id`, `slot_id` | як у `book-slot` і `cancel-booking`, `error` (старий не скасувався — новий видалено) |
| `register-event` | `telegram_id`, `event_id` | `not_registered`, `not_found`, `closed`, `already_registered`, `full` (місткість 0 — без ліміту) |
| `cancel-registration` | `telegram_id`, `event_id` або дія сторінки | `not_found` |
| `rate-event` | `telegram_id`, `event_id`, `rating` 1–5 | `invalid_rating`, `not_found` |
| `book-bst` | `telegram_id`, `session_id` | `not_registered`, `not_found`, `closed`, `already_registered`, `full` (з `actions: ["join-waitlist"]`); рядок черги людини стає `booked` |
| `join-waitlist` | `telegram_id`, `session_id` | `not_registered`, `not_found`, `closed`, `already_registered`, `not_full` (з `actions: ["book-bst"]`), `already_waiting` |
| `cancel-bst` | `telegram_id`, `session_id` або дія сторінки | `not_found`; звільнене місце: перший `waiting` за `added_at` стає `offered` і отримує кнопки `b:ok:<сеанс>` / `b:wx:<сеанс>` |
| `generate-slots` | — | слоти з шаблонів на HORIZON_DAYS днів; наявні не дублюються |
| `send-notice` | дія сторінки події чи сеансу або `{ kind: "event" \| "bst", id }` | `not_found`, `notice_empty`, `notice_unchanged` |

Атомарність: запис на слот, подію й сеанс — один `insertIf` таблиці з обмеженнями (F8-02), тож 20 одночасних записів на
один слот дають рівно один запис (`PsySupportTemplateConcurrencyTests`). Правила перевіряють `PsySupportTemplateRuleTests`
(`openbp run --pin` з даними відносно поточного часу), імпорт шаблону — `ProjectTemplateCatalogTests`.

## Сценарій бота

`bot` — один сценарій на всі оновлення Telegram, за структурою `docs/psy-support.md` §6:

```
Telegram (webhook, X-Telegram-Bot-Api-Secret-Token) → Розбір → Налаштування · Людина · Я психолог → Маршрут
  → Лічильник (counters, increment)
  → Дія (switch за кодом кнопки) → Зареєструвати / Прив'язати психолога / підсценарій F8-08 / Перегляд матеріалу
  → Після дії → Потрібні … (читає лише таблиці свого розділу) → Екран: <розділ>
  → Відповідь → Змінити повідомлення | Надіслати повідомлення · Сповіщення · Команди /psy · Файл матеріалу
```

- Приватні чати; кнопку підтверджено (`answer_callback_query`) одразу. Повтор оновлення відкидає `idempotencyKey`
  (`update_id`).
- Ключі рядків у кнопках — base64url з 22 символів (`callback_data` ≤ 64 байти; найдовший код `c:mo:<запис>:<слот>` —
  50 байт).
- Дії виконують підсценарії правил (`core.executeWorkflow`, `ref:<slug>`) — ті самі, що й дії сторінок; бот лише показує
  їхній `message` і надсилає `notifications` психологам.
- Кнопка, чий рядок уже не існує або не стосується людини, дає «Ця кнопка вже неактуальна» і головне меню.
- `saveSuccessfulData: false` (телефони й факт запису — ТЗ §8), часовий пояс `Europe/Kyiv`.

Підключення тестового бота:

1. Створіть credential `webhook.header` «Секрет вебхука бота психологічної підтримки» з `{ "token": "<випадковий
   секрет>" }` і змінну `psy_telegram_server` (див. вище).
2. Зареєструйте вебхук tool'ом `set_webhook` конектора Telegram: `url` — `<публічна адреса>/webhook/psy-support-bot`,
   `secret_token` — той самий секрет.
3. Активуйте сценарій `bot`, а потім `scheduler`.

### Карта екранів

| Екран | Кнопки й коди | Що відбувається |
|---|---|---|
| Реєстрація (новий, будь-яке повідомлення) | «Поділитися номером» (contact) | свій контакт → `users` (`insertIf`, номер унікальний); чужий контакт, номер зайнятий іншим Telegram — пояснення |
| Після реєстрації | клавіатура «🏠 Головне меню» + меню | психолога, чий телефон збігся, прив'язано до Telegram, йому — команда `/psy` |
| Головне меню `m:psy` | допомога, консультація, БСТ, події, матеріали, термінова допомога, кабінет (психологу) | ТЗ §3 |
| «Мені потрібна допомога» `m:help` | консультація, події, матеріали, термінова допомога | `TEXT_HELP`, ТЗ §4.1 |
| Термінова допомога `m:sos` | меню | `TEXT_SOS`, ТЗ §4.6 |
| Консультації `m:cons` | психологи `c:p`, «Мої записи» `c:my` | ТЗ §4.2 |
| Психолог `c:p` → формат `c:f` → дата `c:d` → час `c:t` → підтвердження `c:ok` | онлайн/офлайн лише якщо в психолога обидва формати; дати й час — вільні слоти у вікні MIN_HOURS_BEFORE…HORIZON_DAYS | `book-slot`; успіх — посилання Google і Outlook «додати в календар», психолог отримує сповіщення |
| Мої записи `c:my` → `c:x` → `c:xx` | скасування з підтвердженням | `cancel-booking`; пізніше MIN_HOURS_BEFORE — пошта психолога |
| Перенесення `c:mv` → `c:md` → `c:mt` → `c:mo` | інша дата й час того самого психолога | `move-booking` |
| Події `m:ev` → картка `e:<id>` | `e:ok` реєстрація, `e:x` скасування, після події `e:fb:<id>:1…5` | `register-event`, `cancel-registration`, `rate-event`; повна подія — «місць немає» |
| БСТ `m:bst` → сеанс `b:s` | `b:ok`, `b:x`, у повний — `b:w` у чергу, `b:wx` вийти; `b:mv` → `b:mt` → `b:mo` перенесення | `book-bst`, `cancel-bst`, `join-waitlist`; перенесення — новий запис, потім скасування старого (новий не вдався — старий лишається) |
| Матеріали `m:mat`, `mt:p:<n>`, архів `mt:arch:<n>` | по 8 на сторінку, ◀️ ▶️ | ТЗ §4.5 |
| Матеріал `mt:r:<id>` | «Відкрити» (посилання), «До списку» | текст; файл (`file_type` + `file` — URL або `file_id`) надсилається `send_document`/`send_video`/`send_audio`/`send_voice`; `material_views` +1 |
| Кабінет `/psy`, `p:h` (лише психологу) | записи `p:bk`, сеанси БСТ `p:bst`/`p:b`, події `p:ev`/`p:e` | записи всіх психологів на PSY_PEER_VIEW_DAYS днів, ім'я й телефон — лише у своїх; учасники своїх подій і сеансів |
| Оголошення `p:ne` → `p:se`, `p:nb` → `p:sb` | підтвердження | `send-notice` учасникам своєї події чи свого сеансу |

Лічильники (`counters`, ТЗ §8): `psy_section_opened`, `help_opened`, `sos_opened`, `consult_opened`, `events_opened`,
`bst_opened`, `materials_opened`, `material_views` — рядки є в шаблоні, бот робить `increment`.

Тести: `PsySupportTemplateBotTests` — кожен шлях ТЗ §9 і кабінет через `openbp run --pin` проти мока Telegram
(`FakeServer --mock telegram`); кнопку наступного кроку тест бере з екрана попереднього.

## Шедулер

`scheduler` — розклад кожні 5 хвилин (`*/5 * * * *`), одне виконання за раз (`concurrency: { max: 1, onLimit: drop }`:
розклад не має ключа кореляції, тож `skipIfActive` тут не діє). Місцевий час — у поясі `settings.timezone`.

```
Кожні 5 хвилин → Налаштування · Уже надіслано · Консультації · Сеанси БСТ → Записи на сеанси · Події → Учасники подій
  · Нові матеріали → Користувачі · Черга повідомлень → План → Зайняти (insert у reminders) → Що надіслати → send_messages
                                                                           → Слоти цього тижня? → generate-slots
                                                                           → Знеособити сьогодні? → старі записи → update
```

| Що | Коли | Кому | Рядок `reminders` (`kind`, `target_id`, `offset_min`) |
|---|---|---|---|
| Нагадування про консультацію | за `REMINDER_MINUTES` (типово 1440, 60, 10 хв) до початку | людині, кнопка «Мої записи» | `booking`, запис, хвилини |
| Нагадування про сеанс БСТ | так само | активним записаним, кнопка сеансу | `bst`, запис на БСТ, хвилини |
| Нагадування про подію | так само | активним учасникам, кнопка події | `event`, реєстрація, хвилини |
| Опитування «Оцініть від 1 до 5» | 1–24 год після початку події | учасникам без оцінки; кнопки `e:fb:<подія>:1…5` бота | `feedback`, реєстрація, 0 |
| Ранковий список | 08:00–12:00, раз на день | психологу з `telegram_id`: сьогоднішні консультації (час, ім'я, без телефонів) | `digest`, `<психолог>:<дата>`, 0 |
| Новий матеріал | опубліковано за останню добу | усім зареєстрованим (до 1000 за прогін), кнопка `mt:r:<id>` | `material`, матеріал, 0 |
| Слоти з шаблонів | щонеділі | підсценарій `generate-slots` | `slots`, дата, 0 |
| Знеособлення | щодня від `RETENTION_HOUR` (типово 3) | `bookings` (`telegram_id`, ім'я, телефон), `event_registrations`, `bst_bookings`, `waitlist` (`telegram_id`, ім'я) старші за `RETENTION_MONTHS` (12) — по 500 кожної таблиці за день | `retention`, дата, 0 |
| Черга `outbox` | щоразу | `chat_id` рядка; рядок позначається `sent_at` | — |

- **Один раз.** «План» відкидає вже надіслане за останні 26 год, а «Зайняти» вставляє рядок `reminders`; unique
  (`kind`, `target_id`, `offset_min`) відмовляє повтору (зокрема одночасному прогону), і таке повідомлення не йде.
  Рядок вставляється до надсилання: збій Telegram не дає дубля, але й повтору не буде.
- **Найближче нагадування.** Якщо одночасно настало кілька (сервер стояв, запис зроблено за 2 год до початку), надсилається
  лише найближче до початку, решта позначаються без повідомлення. Запис, зроблений уже всередині вікна нагадування, за це
  вікно нагадування не отримує — підтвердження щойно прийшло.
- **Підтвердження й зміни** людині й психологу надсилають самі підсценарії правил одразу (F8-08); `outbox` — черга для
  повідомлень, складених поза діалогом (сторінки, інші сценарії): рядок з `chat_id`, `text`, `reply_markup`.
- `saveSuccessfulData: false`; тексти повідомлень — без телефонів (`docs/psy-support.md` §8).

Тести: `PsySupportTemplateSchedulerTests` (`openbp run --pin --now` — кожен вид повідомлення, повтор і відмова unique,
пакети по 100, слоти, знеособлення), `PsySupportTemplateConcurrencyTests` (воркер і Postgres: знеособлення і два прогони
— по одному рядку `reminders`).
