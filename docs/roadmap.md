# Дорожня карта OpenBP_builder

Поточний етап: **1**. Позначай виконані пункти `[x]`.
Кожен етап закінчується робочою версією, яку можна перевірити руками.

Нижче для кожного етапу — готовий промпт для Claude Code. Копіюй його цілком.

---

## Етап 1. Каркас і ядро двигуна (~3 тижні)

- [ ] монорепо pnpm + Turborepo, TS strict, ESLint, Prettier, Vitest
- [ ] docker-compose: postgres, redis
- [ ] `packages/shared`: zod-схема workflow JSON за `docs/workflow-format.md` + валідатор (порти, DAG)
- [ ] `packages/nodes-sdk`: `defineNode`, типи `ctx`, `Item`
- [ ] `packages/expressions`: обчислення `{{ }}` у QuickJS
- [ ] `packages/engine`: черга готових вузлів, items, кілька виходів, Merge, retry, continueOnFail, AbortSignal, інтерфейс `ExecutionStore` (in-memory реалізація для тестів)
- [ ] вузли: `core.manualTrigger`, `core.set`, `core.if`, `core.merge`, `core.code`
- [ ] CLI `pnpm openbp run ./examples/x.json` — виконує сценарій і друкує результат кожного вузла

**Готово, коли:** приклад IF → дві гілки → Merge виконується з CLI, тести зелені.

> Промпт: «Прочитай CLAUDE.md і всі файли в docs/. Виконай Етап 1 з docs/roadmap.md. Почни з плану (список файлів і порядок), покажи його мені, потім реалізуй по пунктах, після кожного пункту запускай тести. Наприкінці відміть виконане в roadmap.md.»

## Етап 2. API, БД, воркер (~3 тижні)

- [ ] `packages/db`: схема з `docs/architecture.md`, міграції
- [ ] `apps/api`: CRUD workflows + версії, запуск вручну, список/деталі виконань, авторизація (email+пароль, JWT у httpOnly cookie), ролі
- [ ] `apps/worker`: BullMQ-воркер, Postgres-реалізація `ExecutionStore`, відновлення після падіння
- [ ] тригери: `core.webhook`, `core.schedule`
- [ ] вузли: `core.httpRequest`, `core.wait`, `core.switch`, `core.loop`

**Готово, коли:** сценарій зберігається через API, запускається webhook-ом і за розкладом, історія видна через API.

> Промпт: «Етап 2 з docs/roadmap.md. Спершу план, потім реалізація. Двигун не чіпаємо без потреби; якщо треба змінити його інтерфейс — опиши навіщо.»

## Етап 3. Канвас (~4 тижні)

- [ ] список сценаріїв, створення, перейменування, активація
- [ ] канвас на React Flow: палітра вузлів (пошук, групи), з'єднання, копіювання, undo/redo, автозбереження
- [ ] панель вузла: форма зі схеми, поле виразу з підказками змінних, Monaco для Code
- [ ] тестовий запуск сценарію і окремого вузла, перегляд input/output (таблиця / JSON), pinned data
- [ ] живий статус вузлів під час тестового запуску (WS/SSE)

**Готово, коли:** сценарій з PRD №1 збирається і тестується повністю з браузера.

## Етап 4. Журнал виконань і надійність (~2 тижні)

- [ ] журнал: фільтри, деталі, повторний запуск, скасування
- [ ] error-workflow, таймаути, очищення старої історії
- [ ] метрики: кількість/тривалість/помилки по сценаріях

## Етап 5. Credentials (~2–3 тижні)

- [ ] шифроване сховище, UI створення/редагування, тест підключення
- [ ] типи: API key, Basic, Bearer, OAuth2 (authorization code), підключення до БД

## Етап 6. Інтеграції під наші сценарії (~3–4 тижні)

- [ ] Postgres, MSSQL, Email (SMTP), Telegram, Microsoft Graph (Teams, Outlook), Google Sheets

**Готово, коли:** усі три сценарії з PRD працюють.
