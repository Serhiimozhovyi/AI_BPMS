# Зручні сторінки застосунку: кабінет психолога і конструктор

Концепція задач F8-14…F8-20. Контракт сторінок — `docs/projects.md` §3; тут — що додаємо і чому.

## Навіщо

Власник (2026-10-29): адмінка психолога в OpenBP має бути не «просто таблицями», а такою ж зручною, як окремий
застосунок `connectors/psy-support/web` (F3-35), і такий конструктор має бути в самому OpenBP — для будь-якого
проєкту, не лише для бота.

Що було в окремому застосунку і чого бракує сторінкам проєкту (F8-04, F8-05):

| Окремий застосунок | Сторінки проєкту зараз | Розрив |
|---|---|---|
| Одна сторінка «Події»: список, редагування збоку, учасники й оголошення під вибраною подією | список → окрема картка → окрема форма | редагування й підлеглі списки на тій самій сторінці |
| «Місця: 3 / 8», черга БСТ поруч | лише колонки рядка | обчислювані колонки (кількість пов'язаних) |
| Стан кольоровою міткою (вільно, зайнято, закрито) | текст значення | мітки з кольорами |
| Вибір психолога над розкладом | пошук рядком | панель фільтрів (вибір, стан, період) |
| Розклад як перелік слотів | таблиця | тижневий календар |
| Своє меню розділів, вхід одразу в розклад | вкладка «Застосунок» у рамці OpenBP | оболонка застосунку: назва, меню, головна сторінка |
| Облікові записи й запрошення психологів | лише SQL | F8-13 |

## Головні рішення

1. **Без коду предметної області.** Усе нове — параметри сторінок у `project_pages.definition`; `src/` і
   `apps/web/src` не знають про психологів (архітектурний тест F7-08 лишається зеленим).
2. **Два нових види сторінок і розширення `list`.**
   - `list` отримує `filters` (керовані користувачем: вибір значення, стан-чипи, період), `badges` (колір за
     значенням), `computed` (кількість чи сума пов'язаних рядків з умовою), `layout: table | cards`,
     `editor: { form, mode: "drawer" }` (форма відкривається боковою панеллю без переходу) і `expand` (підлеглі
     списки під вибраним рядком — як `related` у `detail`, з діями).
   - `calendar` — тиждень / день / місяць над таблицею з колонками початку й тривалості: колір за `badges`,
     клік по події — бокова панель картки чи форми, клік по вільній клітинці — форма з підставленим часом, фільтри як
     у `list`.
   - `dashboard` — головна сторінка з блоків: плитки `metrics`, короткий список (`list` з лімітом), «сьогодні» з
     календаря, кнопки дій. Блок посилається на інші сторінки або містить їхнє визначення.
3. **Оболонка застосунку.** Проєкт задає `app: { title, icon, home, nav: [{ label, pages[] }] }`. Користувач лише з
   роллю застосунку бачить оболонку без меню OpenBP: назва, групи розділів, головна сторінка. Editor бачить те саме в
   рамці проєкту плюс кнопку «Конструктор».
4. **Конструктор — візуальний.** Кожна нова опція налаштовується формою з живим попереднім переглядом на даних
   проєкту; JSON-редактор лишається запасним. Компоненти й токени — з AC-Kit (Figma лише читаємо).
5. **Права не змінюються.** Фільтри, обчислювані колонки й календар працюють поверх тих самих `filter`, ролей і
   маскування чутливих колонок на сервері; клієнт не може зняти фільтр сторінки.
