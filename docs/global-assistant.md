# Загальний помічник (концепт, F3-108…F3-114)

Запит власника (2026-10-28): помічник — не лише чат у редакторі сценарію, а іконка справа на кожній сторінці, як Copilot.
Він бачить, де користувач зараз, і не обмежується одним сценарієм: обговорив процес — помічник створив таблицю, один-два
сценарії, підказав, що куди додати, допоміг розібрати помилку виконання.

## 1. Що є зараз

- Помічник живе лише в редакторі: `POST /workflows/{id}/assistant` (чат з інструментами над одним сценарієм) і
  `POST /workflows/{id}/draft` (побудова з опису). Змінює тільки визначення відкритого сценарію, нічого не зберігає сам.
- OpenBP уже MCP-сервер з інструментами поверх application-шару (`docs/mcp-server.md`): сценарії, таблиці, виконання,
  задачі, проєкти. Правило 4 (`CLAUDE.md`): REST, UI і MCP викликають один application-шар, окремої логіки «лише для ШІ»
  не буде — загальний помічник користується тими самими інструментами.
- Налаштування моделі: список моделей з основною (F3-107). Основна — хмарна (Gemini, Anthropic…): розмова з кількома кроками
  інструментів на `qwen3:8b` (13/15 у заміру, `docs/workflow-drafter.md`) не витягне; локальна Ollama — запасна.

## 2. Як це має виглядати

- **Панель.** Кнопка «Помічник» у шапці каркасу застосунку (на кожній сторінці; лише для editor і admin — viewer кнопки не
  бачить, рішення власника 2026-10-28). Клік розкриває бічну панель-чат (F3-110: `GlobalAssistantService`, компонент
  `app-global-assistant`). Іконку поверх сторінки ми відкинули: вона перекривала керування канвасу (масштаб) в редакторі.
  Чат редактора (відповідь застосовувалась на незбережений канвас, Ctrl+Z) перенесено в спільну панель (F3-117):
  швидкі дії вузла «Пояснити вузол», «Виправити помилку» (з текстом помилки й входом) і «Написати вираз» відкривають її з
  готовим запитом (`GlobalAssistantService.show({text, send, nodeId})`) і контекстом сценарію та вузла; зміни сценарію
  приходять карткою з планом (F3-116) і застосовуються кнопкою, а не прямою правкою канвасу — тож `Ctrl+Z` їх не
  скасовує, попередній стан лишається в історії версій. У панелі редактора лишилися «Пояснення процесу» й «Описати процес»;
  панелі редактора й спільна не відкриті разом. `POST /workflows/{id}/assistant` лишається в Api для сумісності, але
  інтерфейс його більше не викликає.
- **Картки (F3-111).** Пропозиція змін у розмові — картка `app-proposal-card` на місці кроку, що її створив (`proposalId` у
  репліці `tool`): заголовок дії, для таблиць — план (колонки, видалення, зміни, попередження), для зміни сценарію (F3-116) —
  план `update_workflow`: нові й видалені кроки з назвами й типами, змінені кроки (перейменування, тип, параметри за ключами,
  місце на полотні), нові й прибрані зв'язки, налаштування «було → стало», помилки валідації (з ними «Застосувати»
  недоступне) і попередження; для решти — аргументи й повний JSON у «Параметри»; кнопки «Застосувати» / «Скасувати» шлють `POST …/proposals/{id}`, стан картки — з відповіді Api
  (застосовано з посиланням на створене, скасовано, не вдалося з причиною). Якщо пропозицію вже вирішено в іншій вкладці
  (409 `ASSISTANT_PROPOSAL_DECIDED`), розмова перечитується. Примітки про рішення (`note`) призначені моделі й людині не показуються.
- **Зміна відкритого сценарію (F3-115).** Коли застосована пропозиція (`update_workflow`, `publish_workflow`, `move_workflow`)
  змінила сценарій, що відкрито в редакторі, `GlobalAssistantService.workflowChanged` сповіщає редактор: він перечитує сценарій з Api,
  відкидає відкладену правку автозбереження (інакше вона затерла б зміну помічника) і показує «Помічник змінив сценарій».
  Попередній стан лишається в історії версій. Застосовується саме показаний план: якщо сценарій зберегли після нього
  (автозбереження редактора теж), картка стає «Не вдалося» з `WORKFLOW_PLAN_STALE`, і помічник складає план заново.
- **Розбір помилок (F3-112).** На виконанні зі станом `error` є кнопка «Розібрати з помічником»: вона відкриває панель і одразу
  надсилає запит (`GlobalAssistantService.show({send: true})`) з контекстом виконання та кроку, що впав (`nodeId`). У тексті
  запиту — назва сценарію, вузол, номер спроби й повідомлення помилки (до 1000 символів); вхідні й вихідні дані кроку в нього
  не йдуть. Подробиці модель бере інструментами (`get_execution`), а виправлення пропонує карткою (F3-111). Увага: `get_execution`
  віддає елементи кроків, тож персональні дані з них можуть дійти до моделі; маскуються лише credentials і чутливі колонки таблиць.
- **Контекст сторінки.** До кожного запиту йде короткий опис, де користувач: сторінка, відкритий сценарій (і вибраний
  вузол), виконання, проєкт, таблиця. Не весь вміст: лише ідентифікатори й назви; решту помічник бере інструментами.
- **Розмова з пам'яттю.** Історія зберігається в БД (по користувачу): повернувся на іншу сторінку — розмова та сама.
  Можна почати нову. Ліміт довжини історії, старі репліки стискаються.
- **Дії.** Помічник пише текст і викликає інструменти. Читання (список сценаріїв, таблиць, виконання, кроки з помилкою)
  — одразу. Зміни (створити таблицю, сценарій, змінити сценарій, перенести в групу, перезапустити виконання) — через
  **картку підтвердження**: що саме буде створено чи змінено, кнопки «Застосувати» і «Скасувати». Нічого не робиться без
  кліку; після застосування в чаті є посилання на створене.
- **Розбір помилок.** Поруч із помилковим виконанням кнопка «Розібрати з помилкою» відкриває панель з уже підставленим
  контекстом (виконання, крок, помилка без секретів); помічник пояснює причину й пропонує виправлення сценарію як картку.
- **Підказки «що куди додати».** Помічник відповідає текстом з посиланнями на сторінки застосунку (відкрити таблицю,
  сценарій, налаштування), не створюючи нічого без підтвердження.

## 3. Межі й безпека

- Права користувача: помічник діє від імені того, хто з ним говорить; інструмент, недоступний за роллю, не пропонується.
- Секрети ніколи не потрапляють у запити до моделі, історію й відповіді (`architecture.md` §8): credentials помічник бачить
  лише як назви й типи; рядки таблиць зі стовпцями `sensitive` не читає.
- Ліміти: кроків інструментів на повідомлення, розмір відповіді інструмента, таймаут; кожна змінна дія записується в журнал
  аудиту з позначкою «через помічника».
- Хмарна модель отримує опис процесів і назви; про це — одне речення в «Налаштування → Помічник» (безкоштовний рівень Gemini
  використовує вміст для покращення продуктів Google).

## 4. Задачі

Усі нові інструменти — у application-шарі й MCP (правило 4), UI лише викликає їх.

| Задача | Що | Модель |
|---|---|---|
| F3-108 | Application: `IAssistantSessionService` — розмови (таблиця `assistant_conversations`, історія по користувачу), контекст сторінки, загальний цикл інструментів поверх інструментів MCP; REST `/assistant/conversations…` (SSE) | opus |
| F3-109 | Інструменти запису, яких бракує: `create_table`/`alter_table` у application і MCP (зараз таблиці створюються лише з UI/імпортом проєкту); режим «пропозиція» — інструмент змін повертає план, а застосовує його окремий виклик | opus |
| F3-110 | UI: плаваюча іконка й бічна панель у каркасі (всі сторінки), контекст сторінки, історія розмов, перенесення чату з редактора | sonnet |
| F3-111 | UI: картки підтвердження змін («Застосувати» / «Скасувати»), посилання на створене | sonnet |
| F3-112 | Розбір помилок: кнопка на виконанні, контекст із кроків (`get_execution`, scrubbing), пропозиція виправлення | sonnet |
| F3-113 | Права, ліміти, аудит «через помічника», тести безпеки (секрети не в запитах) | opus |
| F3-114 | Документація: `docs/guide/users.md`, приклади розмов; Playwright з фейковим провайдером | sonnet |

Порядок: F3-109 → F3-108 → F3-113 → F3-110 → F3-111 → F3-112 → F3-114. Без змін у форматі сценарію.

## 5. Рішення власника (2026-10-28)

1. Помічником користуються лише `editor` і `admin`; `viewer` іконки й панелі не бачить, а REST `/assistant/…` для нього — 403.
2. Розмову бачить лише той, хто з нею говорить, і суперадмін (`admin`); інші користувачі, включно з іншими editor, — ні.
