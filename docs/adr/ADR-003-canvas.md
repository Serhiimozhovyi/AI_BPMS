# ADR-003. Бібліотека канвасу для Angular: ngx-vflow

Статус: **запропоновано** (приймається власником при мерджі PR спайку F1-11) · Дата: 2026-10-22

## Контекст

Канвас — центральний екран OpenBP: на ньому автор збирає процес, а після фази 2 ще й бачить живий
статус тестового запуску (F2-H), пізніше канвас стає web-component `<openbp-canvas>` (F4-C).
За ADR-001 ми не пишемо канвас з нуля, а беремо перевірену бібліотеку. Кандидати, які реально
живуть в Angular-екосистемі у 2026 році: **ngx-vflow** (Angular-native, сигнали) і **Rete.js v2**
з `rete-angular-plugin` (фреймворк-агностичний редактор з Angular-рендерером).

Вимоги до бібліотеки (з `architecture.md` §7, `workflow-format.md`, PRD):

- кастомний вигляд вузла (картка з назвою, типом, групою, портами) — палітра з `core.*` і tools MCP-серверів;
- кілька іменованих виходів (IF: `true`/`false`, `continueOnFail` додає `error`), один вихід → кілька ребер, один вхід ← кілька ребер;
- створення з'єднань мишею, drag, zoom/pan, виділення;
- 200 вузлів без лагів (а краще — запас на 1000);
- Angular 22, standalone, Signals, **zoneless** (у `apps/web` немає zone.js);
- ліцензія MIT/Apache/BSD.

## Спайк

Гілка `agent/F1-11-canvas-spike`, коміт `4791108` містить обидва прототипи (`apps/web/src/app/canvas/{vflow,rete}`)
на одній моделі графа (`spike-graph.ts`): 3 вузли з прикладу `workflow-format.md` і генератор
сітки на N вузлів (тригер → IF → … з ребрами `false` у наступний ряд, ≈1,2 ребра на вузол).
Обидва прототипи мають однакову картку вузла, порти, створення з'єднань мишею і перемикаються в
редакторі сценарію: `/workflows/x?engine=vflow|rete&n=200`.

Заміри — Playwright + headless Chromium (CDP), viewport 1400×900, 90 кроків drag/pan, 40 кроків zoom;
`x4` — CPU-троттлінг 4× (емуляція слабкого ноутбука). Час кадру — через `requestAnimationFrame`.
«>33» — кількість кадрів довших за 33 мс (помітні ривки).

Висновки із замірів:

- **Критерій «200 вузлів без лагів» виконують обидві** — навіть на 4× повільнішому CPU усі кадри ≤ 33 мс.
- Без віртуалізації ngx-vflow на 500+ вузлах просідає раніше за Rete: він перераховує сигнали ребер на кожен
  кадр drag/pan, тоді як Rete переміщує DOM-вузли напряму. З увімкненою `optimization.virtualization`
  ngx-vflow рендерить лише видиме і тримає 60 fps на 1000 вузлах; DOM не росте з розміром графа.
- Rete економніший за пам'яттю (власних абстракцій менше), ngx-vflow — за DOM (без віртуалізації ≈ −10 %).

Якісне порівняння:

| Критерій | ngx-vflow 2.7 | Rete.js 2 + rete-angular-plugin 2.7 |
|---|---|---|
| Інтеграція з Angular | Angular-native: `<vflow [nodes] [edges]>`, `ng-template[nodeHtml]`, `<handle>`, сигнали всередині і назовні; **zoneless-ready** | Рендер через **Angular Elements** (`@angular/elements`, peer `zone.js`): кастомний вузол — `@Input() data/emit/rendered`, ручний `cdr.detach()/detectChanges()`. У zoneless-застосунку спайку працює без помилок, але це не підтриманий сценарій плагіна |
| Модель даних | декларативна: масиви `Node`/`Edge` із сигналів, зміни — події `nodesChanges`/`edgesChanges`/`connect` → легко тримати `workflow.json` джерелом правди | імперативна: `editor.addNode/addConnection`, `area.translate`, події через pipes; потрібен шар синхронізації з JSON |
| Порти й ребра | `<handle id>` на будь-якому місці картки; кілька ребер з одного виходу за замовчуванням; криві `bezier/smooth-step/step`, маркери-стрілки, підписи, шаблони ребер | сокети через `refComponent`; позиція сокета рахується з `offsetLeft/Top` (CSS-трансформи ламають лінії — довелось обійти); кілька ребер на порт лише з `multipleConnections: true` |
| Типізація | звичайні generic'и `Node<T>` | `GetSchemes<Node, Connection>` з варіантністю generic'ів: з `ClassicPreset.Connection` напряму не компілюється, потрібен підклас |
| Готові можливості для фаз 2–4 | виділення (click, рамка, Ctrl), snap grid, alignment helpers, minimap, node toolbar, keyboard shortcuts, валідація і reconnect з'єднань, групи/підпотоки, віртуалізація, lazy loading | плагіни: `rete-minimap-plugin`, `rete-context-menu-plugin`, `rete-auto-arrange-plugin`, `rete-history-plugin` (undo/redo), `rete-connection-reroute-plugin`; виділення через `AreaExtensions` |
| Undo/redo | немає вбудованого — робимо над власною моделлю workflow (так чи інакше потрібно: джерело правди JSON) | `rete-history-plugin` над моделлю редактора |
| Залежності | `ngx-vflow` + d3-drag/selection/zoom (+ @types) | `rete`, `rete-area-plugin`, `rete-connection-plugin`, `rete-render-utils`, `rete-angular-plugin`, `@angular/elements` |
| Застереження | один мейнтейнер; API ще змінюється між мінорними версіями | Web Components не перереєстровуються (документована пастка зі старими даними при повторному створенні); `rete-angular-plugin` для кожної мажорної версії Angular — окремий entry `rete-angular-plugin/22` |
| Код прототипу | 1 файл, ~170 рядків | 2 файли, ~240 рядків + обхід позиціювання сокетів |
| Ліцензія | MIT | MIT (проєкт з України) |

## Рішення

Беремо **ngx-vflow**. Причини в порядку ваги:

1. **Zoneless і сигнали.** `apps/web` — zoneless Angular 22; ngx-vflow побудований на сигналах і заявляє zoneless.
   Rete через Angular Elements працює, але вимагає `zone.js` як peer і ручного change detection у кожному
   кастомному компоненті — це постійний податок на кожен вузол, тулбар, підпис.
2. **Декларативна модель = простіший зв'язок із `workflow.json`.** Канвас — лише проєкція формату
   (`workflow-format.md`); з сигнальними масивами вузлів/ребер і подіями змін автозбереження, undo/redo
   і живий статус вузла (F2-H) робляться над нашою моделлю, без окремого шару синхронізації з редактором.
3. **Усе потрібне для F2-F вже вбудовано**: кастомні вузли, ребра з маркерами і підписами, snap, виділення,
   minimap, node toolbar, валідація з'єднань, групи. У Rete те саме збирається з 5–6 плагінів.
4. **Продуктивність із запасом.** 200 вузлів — без зауважень; з віртуалізацією — 60 fps на 1000 вузлах на 4× троттлінгу.

Rete.js програє не продуктивністю (без віртуалізації він навіть кращий), а ціною інтеграції з Angular.

## Наслідки

- `apps/web/src/app/canvas/` — прототип-переможець: `vflow-canvas.component.ts` (картка вузла, порти,
  з'єднання, події) і `spike-graph.ts` (демо-граф і генератор для тестів продуктивності). Прототип Rete
  видалено з гілки; він лишається в історії (коміт `4791108`) разом із замірами.
- У F2-F `VflowCanvasComponent` обгортається у `CanvasComponent` з власним API (вхід — `WorkflowDefinition`,
  виходи — зміни позицій, ребер, виділення), як передбачено `architecture.md` §7, щоб бібліотеку можна було замінити.
- **Віртуалізація вмикається за замовчуванням** (`optimization.virtualization: true`) — саме вона дає запас понад 500 вузлів.
- Залежності `apps/web`: `ngx-vflow`, `d3-drag`, `d3-selection`, `d3-zoom` (+ `@types/d3-*`). Прод-збірка: lazy-chunk редактора з канвасом — 178 кБ (≈42 кБ gzip), initial bundle не змінився.
- Для Vitest/jsdom додано `src/test-setup.ts` із заглушками `ResizeObserver` і `canvas.getContext('2d')`, які потрібні ngx-vflow (віртуалізація малює на canvas). Оновлення — у M-01, з перевіркою changelog: API бібліотеки ще рухається.
- Ризик одного мейнтейнера приймаємо: ліцензія MIT дозволяє форк, а обгортка `CanvasComponent` обмежує площу контакту.
- `CLAUDE.md` вже посилається на ADR-003 («канвас — за ADR-003»); `architecture.md` §7 і `roadmap.md` згадують вибір «після спайку» — уточнити при наступній правці docs (окремою задачею).
