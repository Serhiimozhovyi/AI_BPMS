# Протокол перевірки бота психологічної підтримки на OpenBP

Задача F8-11. Шаблон `examples/projects/psy-support` (бот, правила запису, шедулер, сторінки) запускається на
локальному OpenBP з **тестовим** ботом. Протокол показує, що бот і адміністрування працюють так, як вимагає ТЗ, до того,
як ним скористаються люди.

**Рішення власника (2026-10-29):** даних з Google Таблиць не переносимо. Бот стартує з чистими даними, і все ведеться в
OpenBP: психологів, розклад, події, сеанси БСТ, матеріали й тексти заповнюють на сторінках застосунку проєкту. Тому
сценарію `import-sheets` у шаблоні немає, а перемикання бойового бота замінює розділ «Запуск для людей» нижче.

Продакшн-бот «Astarta psy», n8n і бойова таблиця Google під час перевірки не змінюються.

## 1. Підготовка

| # | Що зробити | Де |
|---|---|---|
| 1.1 | Оновити OpenBP до `main` з F8-10 (шедулер) або новішого. | [§9 Оновлення](README.md#9-оновлення-версії) |
| 1.2 | Підключити конектор Telegram з токеном **тестового** бота. id підключення знадобиться далі. | «Підключення» → «Каталог» → Telegram, [посібник §9](../guide/users.md#9-telegram) |
| 1.3 | Створити змінну інстансу `psy_telegram_server` = id підключення з кроку 1.2. | «Налаштування» → «Змінні» |
| 1.4 | Створити credential `webhook.header` з назвою «Секрет вебхука бота психологічної підтримки» і `{ "token": "<випадковий секрет>" }`. | «Облікові дані» |
| 1.5 | Імпортувати шаблон у новий проєкт. | `/projects` → «Імпортувати проєкт» → `examples/projects/psy-support/bundle.json`, або `openbp import-project` |
| 1.6 | Облікові записи: координатор (власник) і щонайменше один психолог (глобальна роль `viewer`). | [§5 Користувачі й ролі](README.md#5-користувачі-й-ролі) |
| 1.7 | Вкладка проєкту «Учасники»: координатору — роль проєкту `editor` і роль застосунку «Координатор», психологу — `viewer` і «Психолог». | проєкт → «Учасники» |
| 1.8 | Заповнити дані на сторінках застосунку: психолог (ім'я, телефон, формати, «Обліковий запис OpenBP»), шаблон розкладу з дією «Згенерувати слоти», подія, сеанс БСТ на 1 місце, два матеріали (текст і файл), за потреби — тексти бота. | проєкт → «Застосунок» |
| 1.9 | Зареєструвати вебхук тестового бота: tool `set_webhook` конектора з кроку 1.2, `url` — `<публічна адреса OpenBP>/webhook/psy-support-bot`, `secret_token` — секрет з кроку 1.4. | «Підключення» → Telegram → дії → «Тестовий виклик» |
| 1.10 | Активувати сценарій `bot`, потім `scheduler`. | проєкт → «Сценарії» |

Слоти доступні для запису не раніше ніж за `MIN_HOURS_BEFORE` (типово 24 год) і не пізніше ніж за `HORIZON_DAYS`
(21 день) від поточного часу, тож шаблон розкладу має покривати дні після завтрашнього.

## 2. Прохід ТЗ у Telegram

Двоє людей: «людина» (будь-який акаунт Telegram) і «психолог» (акаунт з телефоном, вказаним у картці психолога). Кожен
рядок має відповідник серед автоматичних тестів `PsySupportTemplateBotTests`. Тут перевіряється, що те саме працює зі
справжнім Telegram.

| # | Хто | Дія | Очікується |
|---|---|---|---|
| 2.1 | людина | `/start` | привітання й кнопка «Поділитися номером» |
| 2.2 | людина | поділитися своїм номером | меню; рядок у «Користувачі бота» |
| 2.3 | психолог | поділитися номером з картки психолога | меню, команда `/psy` у меню бота |
| 2.4 | людина | «Мені потрібна допомога», «Термінова допомога» | тексти `TEXT_HELP`, `TEXT_SOS` зі сторінки «Тексти бота» |
| 2.5 | людина | Консультація → психолог → формат → дата → час → «Підтвердити» | «Ви записані», посилання Google і Outlook; психолог отримав сповіщення; запис на сторінці «Записи на консультації» |
| 2.6 | людина | «Мої записи» → перенести на інший час | новий час у боті й на сторінці; психолог отримав сповіщення |
| 2.7 | людина | записатися втретє (ліміт `MAX_ACTIVE_CONSULTS` = 2) | відмова з поясненням |
| 2.8 | людина | «Мої записи» → скасувати | запис скасовано, слот знову вільний |
| 2.9 | людина | Події → картка → «Зареєструватися», потім «Скасувати» | обидві дії видно на сторінці «Реєстрації на події» |
| 2.10 | людина і другий акаунт | БСТ на 1 місце: перший записується, другий — у чергу; перший скасовує | другий отримує пропозицію з кнопками «Підтвердити» / «Відмовитися» |
| 2.11 | людина | Матеріали → текстовий і файловий матеріал | текст, файл надіслано; «перегляди» на сторінці «Матеріали» зросли |
| 2.12 | людина | натиснути кнопку зі старого повідомлення про скасований запис | «Ця кнопка вже неактуальна» і меню |
| 2.13 | психолог | `/psy` → записи, сеанси БСТ, події | записи всіх психологів; телефони лише у своїх |
| 2.14 | психолог | оголошення учасникам своєї події | учасники отримали текст; повтор того самого тексту відхилено |
| 2.15 | людина | `/psy` | кабінет недоступний |

## 3. Шедулер

| # | Що | Очікується |
|---|---|---|
| 3.1 | Запис на слот, що починається приблизно за 25 год | нагадування «за добу» приходить один раз протягом години |
| 3.2 | Опублікувати новий матеріал | усі зареєстровані отримують повідомлення з кнопкою матеріалу протягом 5 хв |
| 3.3 | Психолог з консультацією сьогодні | ранковий список о 08:00–12:00 за `settings.timezone` |
| 3.4 | Журнал виконань `scheduler` | кожні 5 хв, без помилок і без паралельних прогонів |

## 5. Запуск для людей

Новий бот окремий: у бойовому боті Астарти з'являється лише посилання на нього. Тому «перемикання» не змінює ні
бойового бота, ні n8n.

1. Пройти розділи 2–4 на тестовому боті й записати результат нижче.
2. Власник створює в @BotFather робочого бота (або залишає тестового робочим) і повторює кроки 1.2, 1.3, 1.9 з його
   токеном; дані проєкту не змінюються.
3. Координатор заповнює реальних психологів, розклад, події й матеріали на сторінках застосунку; тестові записи
   скасовує.
4. Власник додає посилання на нового бота в бот Астарти (вручну, у n8n). Це єдина зміна в бойовому боті, і робить її
   власник.
5. Відкат: прибрати посилання з бота Астарти й деактивувати сценарії `bot` і `scheduler`. Дані проєкту лишаються.

Вилучення старого конектора `connectors/psy-support` і прикладу F3-31 — F8-12, за командою власника після запуску.

## 6. Результат

Протокол ще не пройдено на локальному OpenBP власника. Тут буде записано дату, версію `main`, результат кожного
рядка розділів 1–4 і знайдені розриви.
