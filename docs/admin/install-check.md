# Протокол перевірки інсталяції за документацією

Критерій фази 4 ([roadmap](../roadmap.md)): OpenBP встановлюється у клієнта за [docs/admin/](README.md) без нашої
участі. Перевірку пройдено дослівно за посібником адміністратора на чистому клоні, без скриптів і налаштувань
розробки.

- **Дата:** 2026-10-24.
- **Версія:** `main` @ `5a2939e` (після F4-16); перевірка оновлення — на тій самій версії (див. крок 9).
- **Середовище:** хмарний Linux-контейнер x86_64, Docker Engine 29.9.2, Compose v5.6.1, вихідний трафік через
  проксі з перевіркою TLS.
- **Хто:** Claude, задача F4-17.

## Що виправлено в цьому PR

- `docs/admin/README.md` §7: `dotnet publish` у контейнері — від імені поточного користувача.
- `docs/admin/README.md` §12: як читати перевірку досяжності конектора; новий рядок про збірку за корпоративним
  проксі з перевіркою TLS (`NU1301`/`NU1900`).
- UI, «Виконання» → деталі: порти кроку без назв (сторінка не знає дескриптора вузла) підписувались як `error`
  (вхід і перший вихід). Тепер — номери `#0`, `#1`; `error` лише для виходу за описаними портами в редакторі.

## Розриви, що лишились

Не заважають інсталяції, але варті окремих задач:

- Тіло запиту, яке не розбирається в модель (напр. `connections` об'єктом замість масиву), дає 400 без тіла замість
  Problem Details з поясненням.
- `$env` у виразах завжди порожній.
- Немає екрана керування користувачами і скидання пароля — лише SQL (§5).

## Що чекає власника

- Реальний домен і сертифікат (перевірено лише самопідписаним через Caddy).
- Клієнт OpenBP у Keycloak «Кіт 2» (realm `astarta`) чи в Entra ID: реєструє власник; сам вхід OIDC покрито тестами
  проти Keycloak у Testcontainers (F4-14).
- Публікація образів у реєстр, щоб клієнт не збирав їх на сервері.
