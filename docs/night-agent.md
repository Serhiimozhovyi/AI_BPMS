# Протокол нічного агента

Нічний агент — планована задача Claude в хмарі з підключеним репо `Serhiimozhovyi/OpenBP_builder`.
Мета: використовувати тижневий ліміт токенів до його скидання (**понеділок 01:00 Київ**), просуваючи беклог без участі власника.

## Розклад

| Запуск | Коли (Київ) | Що |
|---|---|---|
| Нічний | Вт–Сб 01:30 | одна задача з `BACKLOG.md` → PR |
| Недільний добір | Нд 20:00 | до двох задач поспіль; завершити до 01:00 |
| Ранковий звіт | Пн–Пт 07:30 | резюме: PR на рев'ю, `blocked`, що далі |

Ліміт Fable — 50 % від тижневого; планові запуски **не** використовують Fable. Задачі з `model: fable` виконуються вдень із власником.

## Вибір моделі

Поле `model` у задачі. Якщо планована задача не дозволяє обрати модель на запуск, агент читає поле і **пропускає задачу**, чия модель сильніша за ту, на якій він запущений (запис у звіт: `skipped: needs opus`).

| model | Коли |
|---|---|
| `fable` | архітектура, інтерфейси, ADR, рев'ю; вдень |
| `opus` | движок, MCP, валідатори, відновлення, канвас |
| `sonnet` | CRUD, міграції, сторінки, тести, CI, конфіги, конектори за шаблоном |
| `haiku` | документація, chore, оновлення версій |

## Алгоритм одного запуску

1. `git fetch`; `git checkout main`; `git pull`.
2. Прочитати `CLAUDE.md`, `BACKLOG.md`, згадані в задачі файли `docs/`.
3. Обрати **першу** задачу зі статусом `ready`, у якої всі `depends` мають статус `done`, і `model` ≤ поточної моделі.
4. Поставити статус `in-progress <гілка>`, гілка `agent/<ID>-<слаг>`; закомітити тільки цю зміну в `BACKLOG.md` першим комітом гілки.
5. Реалізувати за DoD задачі. Після кожного логічного кроку — `dotnet test` / `npm test`. **Не виходити за межі задачі**: жодних рефакторингів «заодно», жодних змін у `docs/` без потреби, зазначеної в DoD.
6. Перед PR: `dotnet build -warnaserror`, `dotnet test`, `npm run lint`, `npm test`. Червоне → виправити; не вдається за 3 спроби → статус `blocked <причина>`, PR як draft з описом проблеми.
7. Відкрити PR за `.github/PULL_REQUEST_TEMPLATE.md`: ID і назва задачі, що зроблено, як перевірити, чекліст DoD. Статус задачі → `review <#PR>`.
8. Якщо лишився бюджет часу і це недільний добір — повторити з кроку 3 один раз.
9. Нічого не мерджити. Мердж — тільки власник після рев'ю.

## Заборонено агенту

- Змінювати стек, ADR, `CLAUDE.md`, схему формату workflow — це задачі `fable` вдень.
- Працювати над задачею, яка `blocked` або чиї `depends` не `done`.
- Пушити в `main`.
- Записувати секрети, ключі, реальні адреси серверів у репо.
- Видаляти або переписувати чужі гілки.

## Промпт планованої задачі (копіювати в поле «prompt»)

```
Ти — інженер проєкту OpenBP (репо serhiimozhovyi/openbp_builder). Виконай один цикл за docs/night-agent.md:
оновити main, прочитати CLAUDE.md і BACKLOG.md, взяти першу задачу `ready` з виконаними depends і model не вищою за твою,
реалізувати її строго за DoD у гілці agent/<ID>-<слаг>, прогнати всі перевірки, відкрити PR за шаблоном,
оновити статус задачі у BACKLOG.md. Нічого не мерджити, main не чіпати. Якщо задач немає або все blocked —
завершити зі звітом без змін у репо. Наприкінці видай звіт: задача, гілка, PR, що лишилось, що заблокувало.
```

## Промпт ранкового звіту

```
Репо serhiimozhovyi/openbp_builder. Прочитай BACKLOG.md і відкриті PR з гілок agent/*.
Видай звіт до 15 рядків: PR на рев'ю (з одним реченням про кожен), задачі blocked і чому,
наступні 2 задачі ready. Нічого не змінюй.
```

## Що робить власник

- Щоранку: рев'ю PR, мердж або коментар; `blocked` → розблокувати або переформулювати задачу.
- Раз на тиждень (нд вдень, на Fable): нарізати наступні задачі так, щоб у `ready` було ≥ 5 задач для `sonnet`/`opus`.
- Якщо агент тричі поспіль не доходить до PR на одній задачі — задача завелика; розбити.
