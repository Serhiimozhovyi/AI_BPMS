# Конструктор форм: дослідження і рішення (фаза 10)

Запит власника (2026-10-31): «в редакторі форм ще можна, щоб рухати вікна, об'єднувати; знайди найкращі практики
конструкторів форм і допрацюй наш». Документ фіксує, що є зараз, що роблять зрілі конструктори, і які рішення
беремо у формат і UX. Задачі — `BACKLOG.md`, фаза 10.

## 1. Що є зараз

Форма в AI_BPMS живе у трьох місцях, і всі три рендерить один рушій (`apps/web/src/app/forms/form-fields.ts`,
F6-03): JSON Schema `type: object` → поля ngx-formly → сторінка.

| Де | Що зберігається | Як редагується |
|---|---|---|
| `core.formTrigger.schema`, `core.wait` v3 `form.schema`, `core.approval.fields` | JSON Schema у параметрах вузла | **сирий JSON** у багаторядковому полі панелі вузла (`schema-fields.ts`, `kind: 'json'`) |
| сторінка застосунку `kind: form` (`docs/projects.md`) | `definition.fields[] { column, label, description, required, value, copyFrom }`; сервер збирає JSON Schema з типів колонок (`ProjectPageService.FormSchemaAsync`) | прапорці «поле / обов'язкове» біля назв колонок у конструкторі сторінок; порядок — порядок увімкнення |
| публічна сторінка `/form/{path}`, картка задачі, форма сторінки | — | рендер: одна колонка, поля одне під одним, без секцій, без умов |

Чого немає: візуального редактора полів, перетягування, рядків із кількох полів, секцій, умовної видимості,
попереднього перегляду форми з вузла, підписів до варіантів списку (тільки `oneOf` руками в JSON).

## 2. Що роблять зрілі конструктори

Джерела: документація Form.io «Layout components», SurveyJS «Survey Creator overview», публічні довідки Jotform,
Typeform, Google Forms; схема погодження і форми «Кіт 2» (Figma AC-Kit, лише читаємо).

| Практика | Form.io | SurveyJS | Jotform | Google Forms | Typeform |
|---|---|---|---|---|---|
| Палітра типів полів ліворуч, канвас у центрі, властивості праворуч | ✓ | ✓ (toolbox · surface · property grid) | ✓ | палітра плаваюча | ✓ |
| Перетягування для порядку | ✓ | ✓ | ✓ | ✓ (ручка) | ✓ |
| Кілька полів в один рядок | «Columns» — сітка 12 одиниць, ширини задаються, на телефоні — у стовпчик | `startWithNewLine: false` + ширина питання у % | «Form layout» — 2/3 колонки, зміна ширини перетягуванням | — (лише рядок таблиці) | — (одне питання на екран) |
| Групи полів | Field Set (легенда), Panel (заголовок, згортання), Tabs, Well | Panel (заголовок, згортання), Page | секції, розриви сторінок | секції | групи питань |
| Умовна видимість | Conditional (просте правило або JS) | `visibleIf` вираз + вкладка Logic | «Conditions» показати/сховати, пропустити | «Перейти до секції за відповіддю» | Logic jumps |
| Попередній перегляд (десктоп/телефон) | ✓ | ✓ (вкладка Preview, пристрої) | ✓ | ✓ | ✓ |
| Запасний режим JSON | ✓ | ✓ (вкладка JSON) | — | — | — |
| Undo/Redo, дублювання поля, клавіатура | ✓ | ✓ | ✓ | дублювання | ✓ |
| Поле «обов'язкове» одним перемикачем у картці | ✓ | ✓ | ✓ | ✓ | ✓ |

Що з цього цінно нам і чому:

1. **Три панелі** (типи · канвас · властивості) — звичний патерн у всіх п'яти; людина не шукає, де додати поле і
   де його налаштувати. Канвас показує форму такою, як її побачать (WYSIWYG), а не список «назва — тип».
2. **Рядок із кількох полів через сітку 12** (Form.io) — просте правило: ширини в рядку в сумі 12, пресети
   6/6, 4/8, 8/4, 4/4/4, 3/3/3/3; на телефоні рядок завжди розпадається у стовпчик. Це і є «об'єднувати вікна».
3. **Секції з заголовком і згортанням** (Panel/Fieldset) — для довгих форм заяв і анкет; на картці задачі
   погодження секція «Дані процесу» вже згорнута (F3-85) — той самий патерн.
4. **Умовна видимість простим правилом** («показувати, якщо поле ∘ значення»), без JS — як у Jotform і Google
   Forms; вираз Jint лишаємо для сценарію, не для форми. Правило має діяти і на сервері: приховане поле не є
   обов'язковим і не потрапляє у дані.
5. **Перегляд десктоп/телефон і режим JSON** — перегляд справжнім рендером (тим, що на `/form/…`), JSON — як
   запасний і для ШІ-агентів через `/mcp` (схема лишається джерелом правди).
6. **Клавіатурні альтернативи перетягуванню** — ↑/↓, «в рядок із попереднім», Delete, Ctrl+D — за axe (F3-86)
   і для роботи без миші.

## 3. Рішення

### 3.1. Формат: розмітка лишається всередині JSON Schema

Джерело правди не змінюється: схема форми — JSON Schema `type: object` з плоскими `properties` (сервер
`FormSchema` перевіряє дані нею, `/mcp` віддає й приймає її як є, старі сценарії працюють без міграції). Розмітка
й підказки віджетів — анотації `x-openbp-*` (як `x-openbp-widget`/`x-openbp-options` у конекторах, `docs/connectors.md`),
JSON Schema їх ігнорує:

```json
{
  "type": "object",
  "required": ["name", "from"],
  "properties": {
    "name":  { "type": "string", "title": "ПІБ", "minLength": 2 },
    "from":  { "type": "string", "format": "date", "title": "З" },
    "to":    { "type": "string", "format": "date", "title": "По" },
    "kind":  { "type": "string", "title": "Вид", "oneOf": [ { "const": "annual", "title": "Щорічна" }, { "const": "unpaid", "title": "За свій рахунок" } ],
               "x-openbp-ui": { "widget": "radio" } },
    "reason": { "type": "string", "format": "textarea", "title": "Причина", "x-openbp-ui": { "placeholder": "Коротко" } },
    "scan":  { "type": "string", "format": "binary", "title": "Скан заяви" }
  },
  "x-openbp-layout": {
    "sections": [
      { "title": "Хто і коли", "rows": [ [ { "field": "name" } ], [ { "field": "from", "width": 6 }, { "field": "to", "width": 6 } ] ] },
      { "title": "Подробиці", "collapsible": true, "rows": [
          [ { "field": "kind" } ],
          [ { "field": "reason", "visibleIf": { "field": "kind", "operator": "eq", "value": "unpaid" } } ],
          [ { "field": "scan" } ] ] }
    ]
  }
}
```

- `x-openbp-layout.sections[]` — `{ id?, title?, description?, collapsible?, collapsed?, rows: cell[][] }`; `cell` —
  `{ field, width? (1–12, типово порівну), visibleIf? }`. Поля `properties`, яких немає в розмітці, рендеряться
  в кінці по одному в рядок (форма без розмітки виглядає як зараз). Поле в розмітці без властивості — помилка
  валідації (`PARAMETER_INVALID` на `/parameters/schema`, як зараз для некоректної схеми). Порядок ключів у
  `properties` конструктор підтримує рівним порядку в розмітці (читабельний JSON), але джерело порядку — розмітка.
- `x-openbp-ui` на властивості — `{ widget?: "radio" | "chips", placeholder?, rows? }` (`radio` — список до 6
  варіантів кнопками; `chips` — множинний вибір чипами; `rows` — висота багаторядкового поля).
- `visibleIf` — `{ field, operator: eq | ne | contains | isEmpty | isNotEmpty | gt | lt, value? }` (оператори ті
  самі, що в умовах сторінок, `docs/projects.md`); одне правило на поле або секцію (`visibleIf` і на секції).
  Сервер застосовує правило до надісланих даних: приховане поле не обов'язкове, його значення відкидається.
- Сторінка застосунку `kind: form`: та сама розмітка в `definition.formLayout` (ключі полів = назви колонок);
  `FormSchemaAsync` переносить її у згенеровану схему як `x-openbp-layout`, а `fields[].ui` → `x-openbp-ui`. Один
  рендер на всі форми.

Відхилено: окреме дерево компонентів як у Form.io (вкладені поля в розмітці) — зламало б `FormSchema`, `/mcp`,
`toPayload` і всі наявні форми; вкладені об'єкти у даних форми нам не потрібні — сценарій очікує плоскі `fields`.

### 3.2. UX конструктора

Спільний компонент `bp-form-designer` (`apps/web/src/app/forms/designer/`):

- **Три панелі.** Ліворуч — типи полів (Текст, Довгий текст, Число, Пошта, Телефон, Адреса, Дата, Дата й час,
  Так/Ні, Вибір, Кілька варіантів, Файл) і «Секція». У центрі — канвас: форма як на сторінці, кожне поле —
  картка з ручкою перетягування, підписом, типом і зірочкою обов'язковості; клік — вибір. Праворуч — властивості
  вибраного: ключ (генерується з підпису латиницею, редагований), підпис, підказка, плейсхолдер, обов'язкове,
  типові обмеження (довжина, мін/макс, шаблон), варіанти списку з підписами (перетягування порядку), значення за
  замовчуванням, «Показувати, якщо». Для сторінки застосунку палітра — колонки таблиці, яких ще немає на формі;
  у властивостях додатково `value` (ставить сервер) і `copyFrom`.
- **Рухати:** перетягування картки (CDK drag-drop, як групи сценаріїв F6) у межах секції й між секціями;
  клавіатура — ↑/↓ переміщують вибране поле, Delete видаляє, Ctrl+D дублює, Ctrl+Z/Ctrl+Shift+Z — undo/redo.
- **Об'єднувати:** картку тягнуть на лівий або правий край іншої — вони стають рядком (ширини порівну), у рядку
  до 4 полів; пресети ширин у властивостях рядка (6/6, 4/8, 8/4, 4/4/4, 3/3/3/3) або перетягування межі між
  клітинками з кроком сітки; тягнуть поле вниз/вгору — виходить з рядка. Клавіатура: «В один рядок із попереднім» /
  «Окремим рядком» у властивостях.
- **Секції:** «Додати секцію» в палітрі; заголовок і опис редагуються на канвасі; згортання; перетягування
  секцій цілком; порожня секція видаляється кнопкою.
- **Перегляд:** перемикач «Конструктор · Перегляд · JSON»; перегляд — справжній рендер `/form/…` із шириною
  1024 і 390 px; JSON — двосторонній, помилки розбору показуються, зміни з JSON потрапляють у конструктор.
- **Де відкривається:** у панелі вузлів `core.formTrigger`, `core.wait` (`mode: form`) і `core.approval` поле
  схеми стає кнопкою «Налаштувати поля (N)» з коротким переліком полів — конструктор відкривається
  повноекранним діалогом (панель вузла завузька); у конструкторі сторінок застосунку для `kind: form` — на місці
  прапорців «Поля».
- Дизайн — фаза 9 (`docs/design-system.md`): картки полів `--bp-bg`/`--bp-line`, вибрана — рамка `--bp-primary` +
  кільце `--bp-tonal`, місце скидання — пунктир `--bp-accent`; списки — `mat-select` + `bp-select-search`.

## 4. Межі

- Формат сценарію (`docs/workflow-format.md`) не змінюється: анотації всередині параметра `schema` — не нові поля
  вузла; версія формату та сама. Опис анотацій додається до §«Форми».
- Вкладені об'єкти й масиви об'єктів (повторювані групи) — не в цій фазі; таблиця/повторювана група — окрема задача
  після досвіду використання.
- Багатосторінкові форми (кроки «Далі/Назад») — не в цій фазі; секції зі згортанням покривають довгі форми.
