# OpenBP_builder — специфікація продукту (PRD)

Версія: 0.1 (чернетка) · Дата: 2026-10-21

## 1. Що це

Самостійно розгорнута (self-hosted) платформа автоматизації процесів у стилі n8n.
Користувач збирає сценарій на канвасі з вузлів: тригер запускає ланцюжок, дані (JSON) проходять через вузли, вузли звертаються до зовнішніх систем.

## 2. Навіщо свій продукт

- повний контроль над кодом, даними й ліцензією (можна вбудовувати у власні продукти й розповсюджувати);
- вузли під внутрішні системи компанії (ERP, облік техніки, агро-сервіси) як «рідні», а не через HTTP-обхідні шляхи;
- власні правила доступу і вхід через корпоративний акаунт;
- інтерфейс українською.

## 3. Користувачі

| Роль | Що робить |
|---|---|
| Автор сценаріїв (аналітик, «просунутий» менеджер) | Збирає сценарії на канвасі, тестує, вмикає |
| Розробник | Пише нові вузли через SDK, підключає внутрішні API |
| Адміністратор | Користувачі, ролі, credentials, моніторинг |
| Глядач | Дивиться журнал виконань, без права змінювати |

## 5. Функції MVP

**Канвас**
- додавання вузлів з палітри, з'єднання, видалення, копіювання
- панель налаштувань вузла (форма генерується зі схеми)
- тестовий запуск усього сценарію або одного вузла; перегляд вхідних і вихідних даних кожного вузла
- «закріплені» тестові дані (pinned data) на вузлі
- автозбереження, версії сценарію

**Виконання**
- тригери: ручний, Webhook, розклад (Cron)
- вузли-логіка: IF, Switch, Merge, Loop over items, Wait, Set/Edit fields, Code (JS)
- вузли-інтеграції: HTTP Request, Postgres, MSSQL, Email (SMTP), Telegram, Microsoft Teams/Outlook (Graph), Google Sheets
- повтори при помилках, таймаут на вузол і на сценарій
- error-workflow: окремий сценарій, який запускається при падінні

**Журнал виконань**
- список запусків зі статусом і тривалістю, фільтри
- деталі запуску: дані на кожному вузлі, помилка зі стеком
- повторний запуск

**Credentials**
- зашифроване сховище; типи: API key, Basic, OAuth2, підключення до БД
- credentials прив'язуються до вузлів за id, у сценарії зберігається лише посилання

**Доступ**
- користувачі, ролі (admin / editor / viewer), вхід email+пароль; Entra ID — етап 7

## 6. Поза MVP

AI-вузли (LLM, агент з інструментами), шаблони сценаріїв, маркетплейс вузлів, підпроцеси (Execute Workflow), мультитенантність, людські задачі/погодження (BPMS-частина), DMN-правила.

## 7. Нефункціональні вимоги

- до 50 одночасних виконань на одному воркері; горизонтальне масштабування воркерами
- виконання переживає перезапуск воркера (стан кожного кроку в БД)
- зберігання історії виконань — налаштовуваний строк (за замовчуванням 30 днів)
- розгортання: Docker Compose на одному сервері
